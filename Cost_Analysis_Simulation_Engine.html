  SME / math lens: what CASE is doing under the hood
  
    Monte Carlo + (optional) copula correlation; phasing weights; optional BY→TY conversion.
    
  
      
    
    1. Sample uncertain lines from distributions using uniforms (MC or LHS stratification).
      2. 
    
    2. If correlation is enabled, transform to correlated uniforms via latent normals.
      3. 
    
    3. Allocate each sampled line to FY buckets using weights; then inflate (if TY).
      4. 
    
    4. Compute totals and percentiles from the empirical distribution.
      5. 
  
    

    


    

                
    
                  
    Workflow by Step
    
                  
    1) Setup
    
                  
      
                    
    • Iterations: more iterations = smoother percentiles (slower).
      • 
                    
    • Sampling: LHS is typically “less noisy” than pure Monte Carlo at the same iteration count.
      • 
                  
    

                  
    2) Lines
    
                  
      
                    
    • Each line represents a cost element with a base value, uncertainty, and schedule.
      • 
                    
    • Use row selection + the bulk bar for fast edits (duplicate, delete, assign WBS, apply distributions).
      • 
                  
    

                  
    3) WBS (optional)
    
                  
      
                    
    • Assign WBS codes to enable roll-ups and to explain “where the money is.”
      • 
                    
    • Use the WBS Library for faster assignment and missing‑coverage cleanup.
      • 
                  
    

                  
    4) Schedule
    
                  
      
                    
    • Schedule phasing drives the FY chart. If a line spans multiple FYs, this tool allocates cost based on the chosen phasing.
      • 
                    
    • Use Trapezoid when effort ramps up and down (vs “flat” phasing).
      • 
                  
    

                  
    5) Risk
    
                  
      
                    
    • Correlation is optional, but powerful when costs move together (e.g., shared labor market, shared quantity driver).
      • 
                    
    • Document the rationale/source so reviewers can trace the assumption.
      • 
                  
    

                  
    6) Results
    
                  
      
                    
    • Use Mean / P50 / P80 for headline numbers; use the S‑curve for probability statements.
      • 
                    
    • Use Convergence to verify stability and tune iteration count efficiently.
      •

    Scenarios & Sharing
    
                  
    Scenarios let you save and reuse named input sets (settings + cost lines). They are stored locally in your browser, so you can build a small library for demos and reviews.
    
                  
    Scenario vs Scenario JSON vs Scenario Package
    
                  
      
                    
    • Scenario: a named configuration you can Load / Save / Save As….
      • 
                    
    • Export/Import JSON: exports or imports one scenario (inputs only). Good for emailing a single “case.”
      • 
                    
    • Scenario Package: exports a complete pack (settings + lines + active WBS template selection). Best for formal sharing and repeatability.
      • 
                  
    
                  
    Recommended workflow
    
                  
      
                    
    1. Build inputs → Save As… a scenario name (e.g., Baseline – Cost only).
      2. 
                    
    2. Export Pack to share the full configuration with a reviewer.
      3. 
                    
    3. After running, use top‑bar Export to download a results CSV for briefing/traceability.
      4. 
                  
    
                  
    
                    Note: Results arrays are not persisted in storage to keep files small. Re‑run after importing to regenerate outputs.

    Analyst: Use scenarios for alternatives analysis: different quantities, different phasing, different risk posture, or different funding assumptions.
    
  
    SME: Scenarios store lines, variables, indices, and settings (including seed). They reproduce exactly when shared.
    

    


    
  Sharing & review workflow (recommended)
  
      
    
    1. Save scenario(s) with clear names.
      2. 
    
    2. Export a Scenario Package.
      3. 
    
    3. Reviewer imports the package and runs with the same seed + iterations.
      4. 
    
    4. Discuss: PE%, P50/P80/P90, budget probability, top drivers, FY profile.
      5. 
  
    
  
    Tip: If you change assumptions, export a new package so reviewers don’t see stale results.
    

    


    

                
    
                  
    Iterations & Convergence
    
                  
    Iterations are the number of simulated draws used to build percentiles and charts.
    
                  
      
                    
    • Higher iterations reduce random “wiggle” in P50/P80 and make the S‑curve smoother.
      • 
                    
    • Use the Convergence chart to confirm P50/P80 stabilize as iterations increase.
      • 
                    
    • If Convergence is noisy, increase iterations or switch to LHS.
      • 
                  
    
                


    
  Beginner intuition: why more iterations helps
  
    Iterations are “possible worlds.” With too few iterations, tail outcomes (the rare high-cost cases) may be under-sampled, and P80/P90 can be noisy.
    
  
    
    
    Quick intuition: If a 10% tail matters, 1,000 iterations gives ~100 tail samples; 10,000 gives ~1,000.
    
  
    

    


    
  Analyst guidance: iteration counts you can defend
  
      
    
    • Exploration: 5k–10k
      • 
    
    • Decision-ready P80: 25k–100k (higher if strongly correlated or skewed)
      • 
    
    • Sanity check: rerun with a different seed; results should be similar if converged
      • 
  
    

    


    
  SME note: sampling error
  
    Sampling error decreases with N, roughly like 1/√N for many statistics; quantiles depend on density near the quantile. LHS often reduces noise relative to pure MC.
    

    


    

                
    
                  
    Sampling (Monte Carlo vs LHS)
    
                  
    Standard Monte Carlo (MC) uses purely random draws. Latin Hypercube Sampling (LHS) is a stratified technique that often reduces variance for the same iteration count.
    
                  
      
                    
    • If you want repeatable results, set a Random seed.
      • 
                    
    • If you are applying correlation, the tool uses a Gaussian‑copula approach under the hood (works with MC or LHS).
      • 
                  
    
                


    
  MC vs LHS: how to choose
  
    
    
    
      Monte Carlo (MC)
      
      
        
    • Simple and standard
      • 
        
    • Good default
      • 
        
    • May need more iterations for stable tails
      • 
      
    
    
    
    
    
      Latin Hypercube (LHS)
      
      
        
    • Often smoother at same N
      • 
        
    • Better coverage of probability space
      • 
        
    • Helpful with many uncertain lines
      • 
      
    
    
    
  
    
  
    Reviewer-friendly line: “We used LHS to reduce sampling noise and improve percentile stability.”
    

    


    
  Advanced: LHS + correlation
  
    CASE stratifies base draws (per line), then applies correlation via Cholesky in the latent normal space. This keeps broad coverage while introducing dependence.
    

    


    

                
    
                  
    Uncertainty Distributions
    
                  
    Pick distributions that match what you know. Common patterns:
    
                  
      
                    
    • Triangular / PERT: bounded uncertainty when you can defend min/most‑likely/max.
      • 
                    
    • Normal: symmetric uncertainty (be careful with negative values for costs).
      • 
                    
    • Lognormal: right‑skewed uncertainty for multiplicative drivers (common in cost growth).
      • 
                  
    
                  
    
                    Best practice: use uncertainty bounds that are consistent with how the source data was developed (historical deltas, SME elicitation, or analogous program spread).
                  
    
                


    
  How bounds work in CASE (low% / high%)
  
    Beginner: Bounds are percentages around the base. For $10M with low −20% and high +30%, the effective range is about $8M to $13M.
    
  
    SME: CASE uses a=base*(1+low%), c=base*(1+high%), b=base as the mode for TRI/PERT. NORM uses σ≈(c−a)/4; LOGN treats bounds as approximate P10/P90 and base as the median.
    

    


    
  Distribution chooser (practical guidance)
  
      
    
    • DET: fixed/known value
      • 
    
    • TRI / PERT: you can justify min/most-likely/max
      • 
    
    • LOGN: right-skewed tail (often realistic)
      • 
    
    • NORM: symmetric uncertainty (use with caution)
      • 
    
    • UNIF: bounded, no most-likely
      • 
  
    

    


    
  Worked mini-example (TRI vs PERT)
  
    
    
    Line: Integration Lab Setup
    
    
    Base: $5.0M, Low: −20%, High: +40%
    
    
    TRI = peaked at base with linear taper; PERT = smoother and more weight near base.
    
  
    

    


    

                
    
                  
    Risk & Correlation
    
                  
    Correlation makes cost lines “move together.” Use it when common drivers exist.
    
                  
      
                    
    • Global ρ: one correlation level applied across all lines.
      • 
                    
    • Groups (A/B/C): correlate only within buckets to avoid forcing unrelated lines to move together.
      • 
                    
    • Document a short rationale/source so the assumption is reviewable.
      • 
                  
    
                


    
  Beginner: correlation in plain language
  
    If two costs share a real driver, they often rise and fall together. Example: labor rate changes affect many labor lines simultaneously.
    

    


    
  Analyst: building correlation groups you can defend
  
      
    
    • Labor: SE/PM, SW dev, sustainment labor
      • 
    
    • Hardware: kits, spares, support equipment
      • 
    
    • Ops: recurring training, help desk, hosting
      • 
  
    
  
    Note: ρ too high inflates tail risk; ρ=0 can understate tail risk. Use shared-driver logic + sensitivity runs.
    

    


    
  SME / math: Gaussian copula summary
  
    CASE generates correlated latent normals using an equicorrelation matrix, converts to correlated uniforms with Φ(·), then uses those uniforms to sample each line’s distribution.
    

    


    

                
    
                  
    Schedule Phasing
    
                  
    Schedule phasing allocates each line’s cost across time. This directly drives FY charts and exports.
    
                  
      
                    
    • Fiscal: allocates evenly by fiscal year between start and end.
      • 
                    
    • Partial fiscal: same idea but honors partial‑year spans more explicitly.
      • 
                    
    • Trapezoid: ramps up, holds, and ramps down. Use Ramp % and Skew to shape the curve.
      • 
                  
    
                


    
  Beginner: phasing = “when money is spent”
  
    Phasing changes annual funding needs. CASE lets each line have its own FY profile (dev often front-loaded; production ramps; O&S steady-state).
    

    


    
  Analyst: choosing a phasing approach
  
      
    
    • Partial FY: starts/ends mid-year
      • 
    
    • Trapezoid: ramp up → steady → ramp down
      • 
    
    • Custom weights: match an existing spend plan
      • 
  
    

    


    
  SME: weight math
  
    For each line, weights w(FY) sum to 1. Sampled cost C is allocated as C·w(FY). If output is TY, each FY bucket is then inflated using the APPN index factor for that FY.
    

    


    

                
    
                  
    Base Year (BY), Then Year (TY), and Inflation Indices
    
                  
    CASE treats your entered dollar inputs as Base Year (BY) dollars in the selected Base year (BY). You can display outputs in BY or TY using appropriation-specific index tables.
    
                  
      
                    
    • BY outputs: costs stay in constant dollars (no inflation indexing).
      • 
                    
    • TY outputs: after schedule phasing by fiscal year, CASE applies a factor using your index levels: Factor(FY)=Index(FY)/Index(FY2026).
      • 
                    
    • APPN on each cost line selects which index series to use (e.g., 3600 RDT&E, 3400 O&M, 3080 Other Procurement).
      • 
                    
    • Index levels may use any base (FY2026=1.000, FY2024=1.000, etc.) because CASE uses the ratio to your chosen BY.
      • 
                  
    
                  
    
                    Tip: If TY looks identical to BY, your indices are probably all 1.000 or not filled for the fiscal years in your schedule.
                  
    

    

                
                
    
                  
    Variables
    
                  
    Variables are named inputs you can reuse across multiple cost lines. Define Scalar variables (single values) and FY series variables (values by fiscal year), then reference them inside line formulas (ƒx). FY series variables can be referenced as VAR_FY2026 (specific year) or VAR (sum across FYs). For dollar scalar variables in BY, you can optionally specify a BY fiscal year (blank = use the estimate Base Year). If it differs from the estimate Base Year, CASE converts it to the estimate Base Year using the cost line’s APPN index series. The expression engine is safe and does not use eval().
    
                  
    Naming
    
                  
      
                    
    • Names must be unique (case-insensitive).
      • 
                    
    • Use A–Z, 0–9, and _ only, and do not start with a number.
      • 
                    
    • Example: LICENSE_UNIT_COST
      • 
                  
    
                  
    FY series
    
                  
      
                    
    • FY series variables store one value per fiscal year (e.g., installs per FY, license counts, or constant-dollar amounts by FY).
      • 
                    
    • Reference a specific year in formulas using NAME_FY2027.
      • 
                    
    • Reference the total across the series using NAME (sum).
      • 
                    
    • FY series values do not automatically override schedule phasing (that can be added later if desired).
      • 
                  
    

    Units and basis
    
                  
      
                    
    • Unit is for readability and basic checks (Dollars, Count, Rate, Percent, Other).
      • 
                    
    • Basis applies only to dollar-like units:
                      
        
                        
      • BY: base year dollars (constant dollars in the estimate’s Base Year).
        • 
                        
      • TY: then-year dollars (already escalated).
        • 
                      
      
                    
      • 
                    
    • Non-dollar units use N/A.
      • 
                  
    
                  
    Uncertainty
    
                  
    If Variable uncertainty is enabled in Layering (Run Compare), each variable with a non‑DET distribution is sampled once per iteration. Any cost lines that reference that variable inherit the sampled value (functional correlation). For deterministic variables, choose DET.

    Randomness & reproducibility
    
                          
                        
    
                        
      
                          
    • CASE uses a seeded PRNG (Mulberry32). Same inputs + same seed ⇒ the same run.
      • 
                          
    • Changing any input (lines, distributions, dates/phasing, correlation, indices, iterations, variables) changes results.
      • 
                          
    • For correlated runs, CASE generates correlated standard normals first, then maps them to uniforms via Φ(z) (normal CDF) for distribution sampling.
      • 
                        
    
                      



    Reproducibility checklist (what to record)
    

      
  
    • Scenario name (and exported package filename)
      • 
  
    • Seed, Iterations, Sampling (MC/LHS)
      • 
  
    • Layer toggles (cost uncertainty / variable uncertainty / correlation)
      • 
  
    • Output basis (BY/TY), Base FY, and index table version/source
      • 

    

    
  
    Practical peer-review tip: Include one line in your briefing: “Run reproduced with seed=12345, N=25k, LHS.”
    

    


    

                      
    
                        
    
                          
    Sampling (Monte Carlo vs Latin Hypercube)
    
                          
                        
    
                        
    Monte Carlo (MC): each trial draws new random values for each uncertain input.
    
                        
    Latin Hypercube Sampling (LHS): for each line, CASE permutes n strata (0…n−1). Trial j uses:
    
                        
    u = (perm[j] + rand()) / n
    
                        
    Then CASE converts to a standard normal via z = Φ⁻¹(u). Correlation (if enabled) is applied in normal space before mapping back to u.
    
                        
    Note: LHS reduces noise for percentiles versus pure MC. Runtime is primarily driven by iterations × number of lines.
    
                      



    Sampling algorithm in one page
    

      
  
    1. Generate base draws in (0,1) for each line and iteration (MC random, LHS stratified).
      2. 
  
    2. If correlation is enabled: map to correlated uniforms using a latent-normal model.
      3. 
  
    3. Transform each uniform into a sampled cost using the selected distribution.
      4. 
  
    4. Allocate sampled line cost across FY weights (phasing).
      5. 
  
    5. If output is TY, multiply each FY bucket by the inflation factor for that APPN and FY.
      6. 
  
    6. Sum across lines to get the iteration total; repeat.
      7. 

    


    Worked intuition: why LHS can be smoother
    

    
  
    Pure MC can cluster probability draws by chance. LHS forces coverage across low/mid/high probability strata for each uncertain line, often stabilizing percentiles earlier.
    

    


    

                      
    
                        
    
                          
    Distributions
    
                          
                        
    

                        
    Each line has a base cost and Low/High (%). CASE computes:
    
                        
    min = base · (1 + low%)   ;   max = base · (1 + high%)
    
                        
    Most distributions treat base as a mode/central value. Costs are clamped at 0 (no negative costs).
    

                        
      
                          
    • Deterministic: returns base.
      • 
                          
    • Triangular: mode = base, min/max from Low/High. Inverse‑CDF with breakpoint F=(mode−min)/(max−min).
      • 
                          
    • PERT (Beta‑PERT, λ=4): uses Beta distribution on [min,max] with base as the mode (implemented via Gamma sampling for Beta).
      • 
                          
    • Normal (truncated @ 0): mean = base, σ ≈ (max−min)/4, draw via base + σ·Φ⁻¹(u), then clamp at 0.
      • 
                          
    • Lognormal: requires base > 0. CASE treats Low/High as P10/P90 to infer σ: σ = ln(P90/P10)/(2·1.28155), and uses μ=ln(base).
      • 
                          
    • Uniform: draw uniformly between min/max.
      • 
                        
    

                        
    If base ≤ 0 for lognormal, CASE falls back to deterministic for that draw.
    
                      



    Parameterization used by CASE
    

      
  
    • Bounds: a=base*(1+low%), c=base*(1+high%), b=base.
      • 
  
    • TRI: triangular(a,b,c) inverse-CDF.
      • 
  
    • PERT: Beta‑PERT with λ=4; mean=(a+4b+c)/6; sample Beta(α,β) scaled to [a,c].
      • 
  
    • NORM: σ≈(c−a)/4; sample base+σ·Z; clamp at 0 for costs.
      • 
  
    • LOGN: base treated as median; bounds treated as approximate P10/P90 to infer σ in log-space.
      • 

    


    Worked example
    

    
  
    Base: $10.0M, Low: −20%, High: +30% ⇒ a=8.0, b=10.0, c=13.0 ($M)
    
  
    TRI mean≈(a+b+c)/3=10.33; PERT mean≈(a+4b+c)/6=10.17
    

    

    Distribution selection note: If you expect a long high-cost tail, LOGN is often more realistic than NORM.
    


    

                      
    
                        
    
                          
    Correlation (Gaussian copula)
    
                          
                        
    
                        
    Correlation is applied in normal space using a Gaussian copula:
    
                        
      
                          
    1. Generate independent normals z (via MC or LHS).
      2. 
                          
    2. Apply Cholesky factor L of the target correlation matrix A: y = L·z.
      3. 
                          
    3. Map to uniforms u = Φ(y), then sample each line’s distribution using u.
      4. 
                        
    
                        
    Global ρ: builds an equicorrelation matrix (same ρ for all off‑diagonals). Groups: applies equicorrelation within Corr Group A/B/C only.
    
                        
    CASE warns when ρ is near singular for many lines. For N lines, equicorrelation requires ρ ≥ −1/(N−1).
    
                      



    Gaussian copula steps (what CASE applies)
    

      
  
    1. Generate standard normals z (MC or LHS).
      2. 
  
    2. Apply Cholesky factor L from the equicorrelation matrix to get y=Lz.
      3. 
  
    3. Transform to uniforms u=Φ(y) (Φ = normal CDF).
      4. 
  
    4. Use u to sample each line’s distribution (inverse-transform style).
      5. 

    

    Interpretation: This dependence model increases the chance that multiple lines are high together, which typically raises P80/P90 relative to independence.
    


    

                      
    
                        
    
                          
    Schedule phasing
    
                          
                        
    
                        
    Each line is allocated across fiscal years using weights wFY that sum to 1.
    
                        
      
                          
    • Fiscal / Partial fiscal: compute the number of inclusive days that fall within each FY between Start and End. Weight is proportional to days in each FY.
      • 
                          
    • Trapezoid: uses the same FY buckets but applies a ramp‑up / steady / ramp‑down intensity curve (controlled by Ramp % and Skew) and then normalizes so total weight = 1.
      • 
                          
    • Custom FY: user provides explicit FY weights; CASE normalizes (sum=1) and uses those.
      • 
                        
    
                        
    Implementation detail: End is treated as inclusive (CASE uses an end‑exclusive date of End+1 day).
    
                      



    Phasing math
    

    Each line defines FY weights w(FY) that sum to 1. For sampled line cost C, annual allocation is C(FY)=C·w(FY).
    

    
  
    Example: C=$12M; weights {FY26:0.25, FY27:0.50, FY28:0.25} ⇒ {3,6,3} ($M)
    

    


    Common phasing patterns
    

      
  
    • Development: front-loaded; partial first/last FY common.
      • 
  
    • Production: ramp up → plateau → ramp down (trapezoid).
      • 
  
    • O&S: steady-state with spikes + long tail.
      • 

    


    

                      
    
                        
    
                          
    Inflation / escalation
    
                          
                        
    
                        
    Inputs are assumed to be in Base Year dollars. If Output basis = TY, CASE applies appropriation‑specific indices by FY to convert BY→TY at roll‑up time.
    
                        
    Line-level “Infl” can override the global basis (e.g., keep a line in BY even when outputs are TY).
    
                      



    BY → TY conversion used by CASE
    

    
  
    Factor(FY)=Index(FY)/Index(BaseFY)
    
  
    TY(FY)=BY(FY)×Factor(FY)
    

    

    
  
    Worked: BaseFY=FY26, Index(FY26)=1.000, Index(FY28)=1.061, BY(FY28)=$10M ⇒ TY(FY28)≈$10.61M
    

    

    Inflation rule Off forces Factor=1.0 for that line.
    


    

                      
    
                        
    
                          
    Outputs & percentiles
    
                          
                        
    
                        
      
                          
    • Mean / stdev: computed from the simulated sample array.
      • 
                          
    • Pxx: CASE sorts the sample array and selects the nearest index: idx = round(p·(n−1)).
      • 
                          
    • Histogram: equal‑width bins across [min,max] (default 34; clamped 10–70).
      • 
                          
    • PE percentile: the percentile position of your point estimate within the simulated CDF.
      • 
                        
    
                      



    Percentiles and PE%
    

      
  
    • Pxx is read from the sorted simulated totals (empirical quantile).
      • 
  
    • PE% is the empirical CDF evaluated at the point estimate.
      • 

    


    Budget probability
    

    For budget B: BudgetProb(B)=F̂(B). Overrun probability is 1−F̂(B).
    


    

                      
    
                        
    
                          
    Top drivers (Spearman rank tornado)
    
                          
                        
    
                        
    CASE estimates driver influence using Spearman rank correlation (ρ) between each line’s sampled cost and the sampled total:
    
                        
      
                          
    1. Take sampled trials (subsampled if needed to cap runtime).
      2. 
                          
    2. Convert each vector to ranks.
      3. 
                          
    3. Compute Pearson correlation on ranks (this equals Spearman ρ).
      4. 
                        
    
                        
    Drivers are ranked by |ρ| and displayed in a tornado chart.
    
                      



    Top Drivers methodology
    

    CASE ranks lines by absolute Spearman rank correlation between the line’s sampled costs and the sampled total.
    

      
  
    • Use it to prioritize data refinement and mitigation discussion.
      • 
  
    • Do not over-interpret: wide ranges and strong correlation can elevate a line in the ranking.
      • 
  
    • Iterate: tighten the top drivers first; rerun; watch the list stabilize.
      • 

    


    

                      
    
                        
    
                          
    Convergence advisor
    
                          
                        
    
                        
    After a run, CASE evaluates stability of key percentiles (especially P80) across checkpoints and against a 10k baseline run.
    
                        
    It recommends an iteration count that targets a stable P80 (heuristic; you should re‑run after applying the recommendation).
    
                      



    Convergence heuristic in CASE
    

    CASE evaluates approximate P50/P80 at iteration checkpoints and reports the relative change between the last two checkpoints. If change is within small tolerances, the run is flagged as “likely stable” for those metrics.
    

    Tail caution: P90/P95 can remain noisy after P50 converges. Increase N (and consider LHS) when decisions hinge on high confidence points.
    


    

                      
    
                        
    
                          
    Assumptions & limitations
    
                          
                        
    
                        
      
                          
    • CASE is an analysis sandbox for uncertainty, correlation, and phasing — not an approved cost model by itself.
      • 
                          
    • Percentiles reflect your assumptions (inputs, distributions, indices, correlation choices).
      • 
                          
    • Correlation is modeled via a Gaussian copula; tail dependence and non‑linear dependencies may not be captured.
      • 
                        
    
                      



    Formula engine limits (intentional)
    

      
  
    • Operators: + − * / ^ and parentheses.
      • 
  
    • Functions: MIN, MAX, ABS, ROUND, CEIL, FLOOR.
      • 
  
    • FY series variables are referenced as VAR_FY2028; VAR returns the sum across FYs.
      • 
  
    • Line references: LINE1, LINE2, … reference other line base values (cycle detection included).
      • 

    

    Advanced modeling pattern: If you need complex logic, split it into intermediate variables/lines. That improves readability and peer review.

    Glossary
    
  
    Tip: use the search box to filter terms. You can link to a specific term with its anchor (click a term name to copy a link).
    
  
    
    
    FY (Fiscal Year)
    A 12‑month accounting period used for planning and reporting. The tool phases cost by FY when fiscal phasing is enabled.
    

    
    Point Estimate (PE)
    The deterministic total before uncertainty is applied (i.e., the base costs summed and phased). Used as a reference point in results and Run Compare.
    

    
    PE%
    The percentile position of the point estimate on the S‑curve. Example: PE% = 30 means the point estimate is at P30 (optimistic relative to the modeled uncertainty).
    

    
    CV (Coefficient of Variation)
    A relative uncertainty metric: standard deviation ÷ mean. Higher CV means more spread relative to the average.
    

    
    Mean
    Average of simulated totals. For skewed distributions, the mean can differ from P50.
    

    
    P50 / P80
    Percentiles of the simulated total. P80 means an 80% chance the actual total is at or below that value (given the model’s assumptions).
    

    
    S‑curve (CDF)
    Cumulative distribution function: maps cost → probability. Used for budget confidence statements.
    

    
    Budget Probability
    The probability that simulated total cost is ≤ the entered budget (P(not exceed)). It is read directly from the S‑curve.
    

    
    Iterations
    Number of simulation trials. More iterations generally reduces sampling noise, but takes longer to run.
    

    
    Monte Carlo
    Simulation by repeated random draws from uncertainty distributions.
    

    
    Latin Hypercube Sampling (LHS)
    A stratified sampling technique that often reduces noise vs pure Monte Carlo at the same iteration count.
    

    
    Convergence
    A check that key percentiles (like P50/P80) stabilize as iterations increase. Lack of convergence often means more iterations or unstable inputs.
    

    
    Uncertainty Distribution
    A model of uncertainty around a cost line (e.g., TRI, PERT, LOGN). Choose shapes that reflect what you know and can defend.
    

    
    TRI (Triangular)
    Defined by low / most‑likely (mode) / high. Simple and transparent when you can justify a most‑likely value.
    

    
    PERT (Beta‑PERT)
    A smoothed alternative to triangular using low / mode / high; often used for schedule/cost uncertainty with a defensible most‑likely.
    

    
    NORM (Normal)
    Symmetric distribution defined by mean and standard deviation. Watch for negatives when modeling costs; consider LOGN if costs must stay positive.
    

    
    LOGN (Lognormal)
    Positive, right‑skewed distribution. Useful when over‑runs are more plausible than under‑runs and costs must remain ≥ 0.
    

    
    Correlation (ρ)
    How strongly cost elements move together (−1 to +1). Use when shared drivers exist; avoid “correlating everything” by default.
    

    
    Correlation Mode (Global vs Groups)
    Global applies one ρ broadly; Groups applies separate ρ values within defined clusters (e.g., ρA/ρB/ρC), which is usually more defensible.
    

    
    Gaussian Copula
    A standard technique to impose correlation across non‑normal distributions by correlating underlying normal variables, then transforming back to each line’s distribution.
    

    
    Trapezoid Phasing
    A phasing profile that ramps up, holds, then ramps down (useful for manpower‑like spending). Controlled by Ramp % and Skew.
    

    
    Ramp %
    In trapezoid phasing, the fraction of the schedule spent ramping up and ramping down. Higher ramp % makes a more gradual rise/fall.
    

    
    Skew
    In trapezoid phasing, shifts the plateau earlier or later in time. Use to reflect front‑loaded or back‑loaded effort.
    

    
    WBS
    Work Breakdown Structure: hierarchical product/effort breakdown used for organizing and rolling up costs.
    

    
    Missing Coverage
    WBS items that have no mapped cost lines. Useful for QA: missing coverage often indicates incomplete mapping or a scope gap.
    

    
    Scenario
    A saved set of inputs (lines, settings, options). Use scenarios to compare assumptions without overwriting your work.
    

    
    Scenario Package
    A shareable bundle of scenarios (and supporting libraries/settings). Best for peer review because it preserves structure and intent.
    

    
    Scenario JSON
    A single‑scenario export/import format. Good for backups or moving one scenario between machines.
    

    
    CSV (Import/Export)
    A spreadsheet‑friendly table format. Useful for bulk editing or audit trails, but may not capture every setting the way a Pack does.
    
  
    

    

                
    
                  
    Troubleshooting
    
                  
      
                    
    • Run does nothing: open Diagnostics and check Boot OK / Wired; fix any red input errors.
      • 
                    
    • Percentiles look unstable: increase iterations and check Convergence; consider LHS.
      • 
                    
    • FY phasing looks wrong: confirm line start/end dates and phasing method.
      • 
                    
    • Correlation error: for N lines, Global ρ must be ≥ −1/(N−1). If unsure, start with ρ = 0.

    3. Check distributions: are bounds plausible?
      4.
