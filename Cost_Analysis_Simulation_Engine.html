    5‑Minute Quick Start
    
                  
    This is the fastest path to a defensible “first run” you can iterate on.
    
                  
      
                    
    1. Click Recommended defaults to apply stable settings (does not change your cost lines).
      2. 
                    
    2. Add or edit at least one cost line: Base cost, Distribution, and Start/End.
      3. 
                    
    3. Pick a phasing method (Fiscal / Partial Fiscal / Trapezoid). Use Trapezoid when cost ramps up/down over time.
      4. 
                    
    4. Click Run to simulate.
      5. 
                    
    5. Read the KPIs (Mean / P50 / P80) and the S‑curve. Use P80 − P50 as a simple risk margin.
      6. 
                    
    6. After a run, use top‑bar Export for results CSV, and Export Pack to share inputs for reproducibility.
      7. 
                  
    
                  
    
                    Tip: Hold Shift while clicking Run to execute a quick self‑check (inputs + wiring) before you brief.
                  
    
                
    

                
    
                  
    Workflow by Step
    
                  
    1) Setup
    
                  
      
                    
    • Iterations: more iterations = smoother percentiles (slower).
      • 
                    
    • Sampling: LHS is typically “less noisy” than pure Monte Carlo at the same iteration count.
      • 
                  
    

                  
    2) Lines
    
                  
      
                    
    • Each line represents a cost element with a base value, uncertainty, and schedule.
      • 
                    
    • Use row selection + the bulk bar for fast edits (duplicate, delete, assign WBS, apply distributions).
      • 
                  
    

                  
    3) WBS (optional)
    
                  
      
                    
    • Assign WBS codes to enable roll-ups and to explain “where the money is.”
      • 
                    
    • Use the WBS Library for faster assignment and missing‑coverage cleanup.
      • 
                  
    

                  
    4) Schedule
    
                  
      
                    
    • Schedule phasing drives the FY chart. If a line spans multiple FYs, this tool allocates cost based on the chosen phasing.
      • 
                    
    • Use Trapezoid when effort ramps up and down (vs “flat” phasing).
      • 
                  
    

                  
    5) Risk
    
                  
      
                    
    • Correlation is optional, but powerful when costs move together (e.g., shared labor market, shared quantity driver).
      • 
                    
    • Document the rationale/source so reviewers can trace the assumption.
      • 
                  
    

                  
    6) Results
    
                  
      
                    
    • Use Mean / P50 / P80 for headline numbers; use the S‑curve for probability statements.
      • 
                    
    • Use Convergence to verify stability and tune iteration count efficiently.
      • 
                  
    
                
    


                
    
                  
    Scenarios & Sharing
    
                  
    Scenarios let you save and reuse named input sets (settings + cost lines). They are stored locally in your browser, so you can build a small library for demos and reviews.
    
                  
    Scenario vs Scenario JSON vs Scenario Pack
    
                  
      
                    
    • Scenario: a named configuration you can Load / Save / Save As….
      • 
                    
    • Export/Import JSON: exports or imports one scenario (inputs only). Good for emailing a single “case.”
      • 
                    
    • Scenario Pack: exports a complete pack (settings + lines + active WBS template selection). Best for formal sharing and repeatability.
      • 
                  
    
                  
    Recommended workflow
    
                  
      
                    
    1. Build inputs → Save As… a scenario name (e.g., Baseline – Cost only).
      2. 
                    
    2. Export Pack to share the full configuration with a reviewer.
      3. 
                    
    3. After running, use top‑bar Export to download a results CSV for briefing/traceability.
      4. 
                  
    
                  
    
                    Note: Results arrays are not persisted in storage to keep files small. Re‑run after importing to regenerate outputs.
                  
    
                
    

                
    
                  
    Iterations & Convergence
    
                  
    Iterations are the number of simulated draws used to build percentiles and charts.
    
                  
      
                    
    • Higher iterations reduce random “wiggle” in P50/P80 and make the S‑curve smoother.
      • 
                    
    • Use the Convergence chart to confirm P50/P80 stabilize as iterations increase.
      • 
                    
    • If Convergence is noisy, increase iterations or switch to LHS.
      • 
                  
    
                
    

                
    
                  
    Sampling (Monte Carlo vs LHS)
    
                  
    Standard Monte Carlo (MC) uses purely random draws. Latin Hypercube Sampling (LHS) is a stratified technique that often reduces variance for the same iteration count.
    
                  
      
                    
    • If you want repeatable results, set a Random seed.
      • 
                    
    • If you are applying correlation, the tool uses a Gaussian‑copula approach under the hood (works with MC or LHS).
      • 
                  
    
                
    

                
    
                  
    Uncertainty Distributions
    
                  
    Pick distributions that match what you know. Common patterns:
    
                  
      
                    
    • Triangular / PERT: bounded uncertainty when you can defend min/most‑likely/max.
      • 
                    
    • Normal: symmetric uncertainty (be careful with negative values for costs).
      • 
                    
    • Lognormal: right‑skewed uncertainty for multiplicative drivers (common in cost growth).
      • 
                  
    
                  
    
                    Best practice: use uncertainty bounds that are consistent with how the source data was developed (historical deltas, SME elicitation, or analogous program spread).
                  
    
                
    

                
    
                  
    Risk & Correlation
    
                  
    Correlation makes cost lines “move together.” Use it when common drivers exist.
    
                  
      
                    
    • Global ρ: one correlation level applied across all lines.
      • 
                    
    • Groups (A/B/C): correlate only within buckets to avoid forcing unrelated lines to move together.
      • 
                    
    • Document a short rationale/source so the assumption is reviewable.
      • 
                  
    
                
    

                
    
                  
    Schedule Phasing
    
                  
    Schedule phasing allocates each line’s cost across time. This directly drives FY charts and exports.
    
                  
      
                    
    • Fiscal: allocates evenly by fiscal year between start and end.
      • 
                    
    • Partial fiscal: same idea but honors partial‑year spans more explicitly.
      • 
                    
    • Trapezoid: ramps up, holds, and ramps down. Use Ramp % and Skew to shape the curve.
      • 
                  
    
                
    

                
    
                  
    WBS Mapping
    
                  
    WBS mapping is optional but recommended for traceability and storytelling.
    
                  
      
                    
    • Assign WBS codes to cost lines to enable roll-ups.
      • 
                    
    • Use “Show only missing” to quickly identify unassigned lines.
      • 
                    
    • Roll-ups help answer: “Which branches drive mean cost?” and “Which drive uncertainty?”
      • 
                  
    
                
    

                

    
                  
    Reading Results
    
                  
      
                    
    • Mean: the average simulated total.
      • 
                    
    • P50: “coin‑flip” point; 50% chance actual is below.
      • 
                    
    • P80: common budgeting point; 80% chance actual is below.
      • 
                    
    • S‑curve: use it to make probability statements (“There’s a 20% chance we exceed $X”).
      • 
                    
    • PE%: probability that total cost is ≤ the point estimate (sum of base costs). Lower PE% means your base is optimistic vs modeled uncertainty.
      • 
                  
    
                  
    
                    Quick story: “Our P50 is the most likely planning point; our P80 is a conservative funding point; the difference is the risk margin.”
                  
    
                  
    Tip: Use the Briefing tools card to compute budget probability and to capture talking points like “confidence at $X.”
    
                
    


    
  
    Budget Probability
    
  
    The Budget (total) input lets you compute P(not exceed) from the latest simulation run.
    
  
      
    
    • Enter a total budget value (same units as your costs).
      • 
    
    • The tool evaluates the simulated total-cost distribution and reports the probability that total cost is ≤ your budget.
      • 
    
    • Use this to answer: “If we fund at $X, what confidence do we have?”
      • 
  
    
  
    
    Common briefing language: “At a budget of $X, we have Y% confidence of not exceeding.”
  
    
  
    Note: Budget probability depends on your modeled uncertainty and correlation assumptions. If inputs change, re-run to refresh.
    

    


    
  
    Layering & Run Compare
    
  
    Layering is a review technique: add uncertainty sources one at a time so you can validate assumptions and avoid double counting.
    
  
    Recommended layer sequence
    
  
      
    
    1. Cost uncertainty only (distributions on lines, no correlation).
      2. 
    
    2. + Correlation (Global ρ or Groups A/B/C).
      3. 
    
    3. + Schedule uncertainty / phasing sensitivity (if applicable).
      4. 
    
    4. + Risk register (when modeled as discrete risks; if/when enabled).
      5. 
  
    
  
    Run Compare metrics
    
  
      
    
    • P50 / P80 / Mean: headline points from the simulated totals.
      • 
    
    • PE%: probability total ≤ the point estimate (sum of base costs). Lower PE% implies an optimistic base vs modeled uncertainty.
      • 
    
    • CV: coefficient of variation (σ/μ). Higher CV indicates more relative spread.
      • 
    
    • Layers: which uncertainty toggles were active for that run.
      • 
  
    
  
    
    Tip: Use layering to explain what changed (e.g., “Correlation increased P80 by $X”) instead of only presenting one final curve.

    Cost Line Field Guide
    
  
    Each cost line represents one cost element with a base value, uncertainty, and schedule. Use this guide to avoid the most common input mistakes.
    
  
    Core fields
    
  
      
    
    • Title: short description (e.g., “Software labor”).
      • 
    
    • Base cost: your point estimate for the line before uncertainty.
      • 
    
    • Distribution: the uncertainty shape. The Distribution column includes a pill describing how Low % and High % are interpreted.
      • 
    
    • Low % / High %: low- and high-side adjustments relative to Base cost (interpretation depends on Distribution).
      • 
    
    • Start / End: schedule dates that drive fiscal-year allocation.
      • 
  
    
  
    Phasing (by line)
    
  
      
    
    • Phasing method: Fiscal / Partial Fiscal / Trapezoid.
      • 
    
    • Ramp % (Trapezoid): how much of the span ramps up/down (typical 10–30%, max 45%).
      • 
    
    • Skew (Trapezoid): shifts where the plateau occurs (−1 front-loads, +1 back-loads; total cost unchanged).
      • 
  
    
  
    Correlation (optional)
    
  
      
    
    • Corr Group: A/B/C bucket used only when Correlation Mode = Groups.
      • 
  
    
  
    Status
    
  
      
    
    • Green = OK, Yellow = warning, Red = error. Fix red rows before running.
      • 
  
    
  
    
    Common mistakes: (1) End date before start date, (2) Normal distribution with large negative tail, (3) High % < Low %, (4) Trapezoid Ramp % too high.
  
    

    


    
  
    Glossary
    
  
    Tip: use the search box to filter terms. You can link to a specific term with its anchor (click a term name to copy a link).
    
  
    
    
    FY (Fiscal Year)
    A 12‑month accounting period used for planning and reporting. The tool phases cost by FY when fiscal phasing is enabled.
    

    
    Point Estimate (PE)
    The deterministic total before uncertainty is applied (i.e., the base costs summed and phased). Used as a reference point in results and Run Compare.
    

    
    PE%
    The percentile position of the point estimate on the S‑curve. Example: PE% = 30 means the point estimate is at P30 (optimistic relative to the modeled uncertainty).
    

    
    CV (Coefficient of Variation)
    A relative uncertainty metric: standard deviation ÷ mean. Higher CV means more spread relative to the average.
    

    
    Mean
    Average of simulated totals. For skewed distributions, the mean can differ from P50.
    

    
    P50 / P80
    Percentiles of the simulated total. P80 means an 80% chance the actual total is at or below that value (given the model’s assumptions).
    

    
    S‑curve (CDF)
    Cumulative distribution function: maps cost → probability. Used for budget confidence statements.
    

    
    Budget Probability
    The probability that simulated total cost is ≤ the entered budget (P(not exceed)). It is read directly from the S‑curve.
    

    
    Iterations
    Number of simulation trials. More iterations generally reduces sampling noise, but takes longer to run.
    

    
    Monte Carlo
    Simulation by repeated random draws from uncertainty distributions.
    

    
    Latin Hypercube Sampling (LHS)
    A stratified sampling technique that often reduces noise vs pure Monte Carlo at the same iteration count.
    

    
    Convergence
    A check that key percentiles (like P50/P80) stabilize as iterations increase. Lack of convergence often means more iterations or unstable inputs.
    

    
    Uncertainty Distribution
    A model of uncertainty around a cost line (e.g., TRI, PERT, LOGN). Choose shapes that reflect what you know and can defend.
    

    
    TRI (Triangular)
    Defined by low / most‑likely (mode) / high. Simple and transparent when you can justify a most‑likely value.
    

    
    PERT (Beta‑PERT)
    A smoothed alternative to triangular using low / mode / high; often used for schedule/cost uncertainty with a defensible most‑likely.
    

    
    NORM (Normal)
    Symmetric distribution defined by mean and standard deviation. Watch for negatives when modeling costs; consider LOGN if costs must stay positive.
    

    
    LOGN (Lognormal)
    Positive, right‑skewed distribution. Useful when over‑runs are more plausible than under‑runs and costs must remain ≥ 0.
    

    
    Correlation (ρ)
    How strongly cost elements move together (−1 to +1). Use when shared drivers exist; avoid “correlating everything” by default.
    

    
    Correlation Mode (Global vs Groups)
    Global applies one ρ broadly; Groups applies separate ρ values within defined clusters (e.g., ρA/ρB/ρC), which is usually more defensible.
    

    
    Gaussian Copula
    A standard technique to impose correlation across non‑normal distributions by correlating underlying normal variables, then transforming back to each line’s distribution.
    

    
    Trapezoid Phasing
    A phasing profile that ramps up, holds, then ramps down (useful for manpower‑like spending). Controlled by Ramp % and Skew.
    

    
    Ramp %
    In trapezoid phasing, the fraction of the schedule spent ramping up and ramping down. Higher ramp % makes a more gradual rise/fall.
    

    
    Skew
    In trapezoid phasing, shifts the plateau earlier or later in time. Use to reflect front‑loaded or back‑loaded effort.
    

    
    WBS
    Work Breakdown Structure: hierarchical product/effort breakdown used for organizing and rolling up costs.
    

    
    Missing Coverage
    WBS items that have no mapped cost lines. Useful for QA: missing coverage often indicates incomplete mapping or a scope gap.
    

    
    Scenario
    A saved set of inputs (lines, settings, options). Use scenarios to compare assumptions without overwriting your work.
    

    
    Scenario Pack
    A shareable bundle of scenarios (and supporting libraries/settings). Best for peer review because it preserves structure and intent.
    

    
    Scenario JSON
    A single‑scenario export/import format. Good for backups or moving one scenario between machines.
    

    
    CSV (Import/Export)
    A spreadsheet‑friendly table format. Useful for bulk editing or audit trails, but may not capture every setting the way a Pack does.
    
  
    

    

                
    
                  
    Troubleshooting
    
                  
      
                    
    • Run does nothing: open Diagnostics and check Boot OK / Wired; fix any red input errors.
      • 
                    
    • Percentiles look unstable: increase iterations and check Convergence; consider LHS.
      • 
                    
    • FY phasing looks wrong: confirm line start/end dates and phasing method.
      • 
                    
    • Correlation error: for N lines, Global ρ must be ≥ −1/(N−1). If unsure, start with ρ = 0.
